⚠ Note for Account Managers
There is no SM New Client list. When onboarding a new client, all tasks go into the corresponding discipline lists for that month: design setup tasks in SM Design, content strategy tasks in SM Content, and so on. Use the same task naming format as any other task. This keeps all reporting consistent across new and existing clients.

— What Changed & What to Fix
⚠️ Updated June 2026
Key Changes from the Previous Template
These are the rules that changed since April 2026, plus issues found in live Basecamp data that the whole team needs to be aware of.
1
Changed
AdHoc tasks now have their own list
All unplanned / urgent requests go into SM AdHoc - [Month YYYY]. Do not add AdHoc tasks inside SM Content, SM Design, or SM Multimedia. This keeps the monthly lists clean and makes AdHoc volume trackable separately.
2
Changed
Separator is a hyphen ( - ), not an em-dash ( — )
Every separator in task names and list names uses a plain hyphen with spaces on both sides. No more em-dashes. Examples: REV - Static - Calendar Designs | x4 - R1 not REV — Static — Calendar Designs | x4 — R1
3
Fix Required
Never paste task names from Google Docs, Notion, or other rich text tools
Copy-pasting from those sources introduces invisible characters (like a hidden "Word Joiner" before the text) that make tasks unsearchable. Always type task names directly in Basecamp, or paste as plain text. This has already caused 7+ Caption tasks to disappear from searches in the current data.
4
Fix Required
No trailing line breaks in task names
106 tasks currently have an invisible newline character at the end of their title from copy-pasting. Always check that the task name is clean before saving. This breaks grouping and filters in every report.
5
Changed
List names: always include the full year (not "26")
List names must use the full 4-digit year: SM Content - June 2026 not SM Content - June 26. Also no double spaces, no trailing spaces, no non-breaking spaces. One space on each side of the hyphen, nothing else.
6
Changed
Caption tasks renamed (from "Reels - Concepts & Captions" to "Caption - Concepts for Reels")
The Content list now uses Caption - Concepts for Static | x[Q] and Caption - Concepts for Reels | x[Q] instead of the old combined "Concepts & Captions" format. This keeps the task type consistent with the rest of the system.
7
New
Printing tasks go in their own list
Any offline / print work goes in Printing - [Month YYYY]. Tasks inside use the format Print - [Type] - [Brief Description] | x[Q] where [Type] is one of: Outdoor, Business Card, QR Code, Prescription. Do not use "AdHoc - Print" — the Printing list already implies it's non-SM. Not "Printings", not "Printing - 2026" without a month.
8
Fix Required
Discipline must always match the task type — no "General"
When creating a task, the Discipline field must reflect what the work actually is: Design, Content, Multimedia, or Revisions. "General" is not a valid discipline. For AdHoc tasks, set the discipline based on what the task involves: AdHoc - Static = Design, AdHoc - Caption = Content, AdHoc - Video Edit = Multimedia.
9
New
Partial correction rounds: R[#]-[sub] for internal re-deliveries
When a deliverable within a round was incomplete or incorrect due to an internal error (not a new client request), name it as REV - [Type] - [Description] | x[Q] - R1-1 where the second number is the partial delivery sequence. Example: REV - AI Reel | x2 - R1-1 means the first partial correction within Round 1. Similarly, R0 is used for an internal edit made before any client round officially started. Neither R0 nor R[n]-[m] count toward the client revision count — they track internal accountability only.
10
New
Multimedia sub-tasks: stages are assigned individually but not in the main report
Tasks like AI Reel and Video Edit Reel may have sub-tasks representing production stages (e.g. Animations, First Cut, Finalizing). These appear in each team member's personal assignments and are counted in staff workload, but they are linked to the parent task and do not appear as separate rows in the main report. This is expected behavior — do not duplicate them as standalone tasks in the main list.
— Frequent Errors Found in Live Data
⚠ Based on Basecamp Audit — June 2026
What the Team Is Getting Wrong
These are real patterns found across 821 tasks in the live Basecamp data. Each one breaks search, grouping, or reporting accuracy.
1
Critical
Pasting task names from Google Docs, Notion, or WhatsApp
This is the single most damaging habit. Rich text sources inject invisible Unicode characters (Word Joiner U+2060, Zero Width Space U+200B) that have no visible appearance but break everything. Tasks with these characters become completely unsearchable — a search for "Caption" will return zero results even if the task exists. Found in 7+ Caption tasks in the current data. Always type task names directly in Basecamp, or paste as plain text only.
2
Critical
Trailing line breaks at the end of task names
106 tasks currently end with an invisible newline character from copy-pasting. The task looks completely normal on screen but is treated as a different string by every filter, search, and grouping in the report. These tasks will never match their type, never group correctly, and inflate unknown categories. Always press backspace after pasting to make sure there is no extra line at the end of the task name.
3
Critical
Discipline set to "General" instead of the real discipline
125 tasks are filed under "General" — a category that should not exist. Almost all of these are AdHoc tasks where the person creating the task did not set the discipline. The rule is simple: look at the task type inside the name and set accordingly.

AdHoc - Static → Design    AdHoc - Caption → Content    AdHoc - Video Edit Reel → Multimedia

"General" is not a valid discipline. 125 tasks worth of work is currently invisible to all discipline-level reports because of this.
4
High
Task type set to "Other"
"Other" is not a real task type — it means the task was never properly classified. 17 tasks currently use it. 9 of them are Caption tasks that were simply miscategorized. The remaining 8 need individual review. Going forward: if a task doesn't fit any known type, check the title again. If it genuinely represents a new work type, flag it for the ops lead to add to the standard list — do not default to "Other."
5
High
Wrong list name format — 46 distinct list names found, should be fewer than 15
List names are being created freehand by multiple people with no shared reference. Every variation creates a new isolated bucket in the report. Common violations found in live data:
SM AdHocs - June 2026 → plural "AdHocs"  |  AdHoc - June 2026 → missing "SM" prefix
SM Content —  June 26 → em-dash + double space + 2-digit year
SM Designs - April 2026 → plural "Designs"  |  Printings - 2026 → plural, no month
Revisions  → no prefix, no date, trailing space

Rule: Never create a new list without checking this template first. The only person who should create monthly lists is the ops lead at the start of each month.
6
High
Missing quantity, or "| x" with nothing after it
Every deliverable task must include a quantity in the format | x[Q]. Two failure modes found: (1) no quantity at all — the quantity field is simply left empty; (2) the pipe and letter x are there but the number is missing (e.g. Reel Visuals - B&A Cases Retouching | x). Both cases cause the task to be uncountable in all volume reports.

Inconsistent reel task type names
Five overlapping reel type names are in use simultaneously, making it impossible to aggregate reel volume across projects. The valid types are Video Edit Reel, AI Reel, and B&A Reel. Using anything else creates a separate ungrouped bucket.

8
High
Print and outdoor tasks added to the wrong list
Print work (outdoor signs, business cards, prescriptions, QR codes) is showing up in two wrong places: inside SM Design as "Static - Outdoor" tasks, and inside SM AdHoc as "AdHoc - Print" tasks. All print work belongs in Printing - [Month YYYY] using the format Print - [Type] - [Brief Description] | x[Q]. This is the only way print volume is tracked separately from digital SM work.
9
Medium
Creating one-off custom lists for specific tasks
Several non-standard lists were found created to house specific tasks that had no obvious home. Examples from live data: Video Edit Reel, Video Edit - Finalizing, Video Edit - IG Splitting, Captions & Thumbnails, New Layout\Template - Dr Profiles | x84. All of these represent tasks that belong in the standard monthly lists (SM Multimedia, SM Content, SM Design). Creating a custom list isolates tasks from every aggregation, filter, and report that depends on the standard list names.
10
Medium
Quantity placed in the list name, not the task name
One list was found named New Layout\Template - Dr Profiles | x84 — the quantity belongs in the task title, not the list name. List names are category labels, not task descriptions. Putting a quantity or description in the list name makes it impossible to rename or reuse the list, breaks all list-name-based grouping, and means the quantity is invisible to the task-level report.
11
Medium
Typos in task keyword names
6 completed tasks use Staric instead of Static — all from the same account. These tasks are invisible to any "Static" filter and inflate an unknown category in type breakdowns. Other keyword-level typos (double letters, transposed characters) have the same effect. Task type keywords — Static, Caption, Reel, Thumbnail, Revision, etc. — must be spelled exactly as shown in this template. When in doubt, copy the keyword directly from here.
